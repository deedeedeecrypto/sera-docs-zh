# 常见错误

## `422 {"detail": "Invalid request"}`

**最常见的一个，而且提示完全没用** —— 它不告诉你少了哪个字段。

原因基本只有一个：请求体字段不全或格式不对。
`/swap/quote` 要七个字段，[全部必填](quote-api.md#请求体)。

按这个顺序自查：

1. `from_token` / `to_token` 用的是**合约地址**，不是 `"USDC"` 这种符号？
2. `from_amount` 是**最小单位字符串**？（100 USDC = `"100000000"`，不是 `"100"`）
3. `owner_address`、`recipient` 都填了？（问价也要填，随便一个合法地址）
4. `expiration` 是**未来**的 Unix **秒**？（不是毫秒）
5. `gas_mode` 是 `"receive_less"` 或 `"pay_more"`？

## `400 {"success": false, "error": "no_liquidity"}`

这一对**在这个方向、这个金额上**没有报价。

注意两件事：

**方向是分开的。** A 换 B 能报价，不代表 B 换 A 也能。实测下来，
`USDC → MYRT` 正常报价，`MYRT → USDC` 在 1 / 10 / 100 / 1000 美元四个金额上
全部返回 `no_liquidity`。这不是 bug，是那个方向当时没有挂单。

**换个金额再试。** 流动性是按档位分布的，小额报不出来的对，大额可能可以，反之亦然。

## 报价成功，但 `minOutputAmount` 是 `0`

不是错误。是固定 gas 正好吃掉了全部本金。

实测 1 USDC 换 MYRT 就是这样：gas 固定收 1 美元，本金 1 美元，减完剩零。
2 美元就能正常报出 3.4 MYRT。

**这条对所有能报价的对都成立**，不是 MYRT 特有的。

## 我的服务器请求不通

`api.sera.cx` 在部分云厂商的出口白名单之外。表现是：

```
curl: (56) CONNECT tunnel failed, response 403
```

这是**你这边的网络策略**挡的，不是 Sera 挂了。先用 `GET /health` 从别的网络确认一下。

## `expiration` 到底填什么

Unix 秒，未来时间。稳妥的做法是拿链上时间加十分钟：

```bash
curl -s https://api.sera.cx/api/v1/system/time
```

用本地时间一般也行，但机器时间偏了就会莫名其妙被拒。

## 数字和官网对不上

链上流动性天天变。这个仓库里所有数据都标了实测日期，
**过期了就自己重跑**，命令都在文档里。

看到任何没有标日期的链上数字，都该怀疑一下。
