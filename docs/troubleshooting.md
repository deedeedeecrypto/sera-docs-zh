# 调用清单

把 `/swap/quote` 一次写对要注意的几件事。都是实际调下来记的。

## 七个字段一个都不能省

`/swap/quote` 要七个字段，[全部必填](quote-api.md#请求体)。
问价时用不到的字段也要给值，这是接口的约定，给个合法值就行。

按这个顺序过一遍：

1. `from_token` / `to_token` 用**合约地址**，不是 `"USDC"` 这种符号。地址从 `/tokens` 拿
2. `from_amount` 是**最小单位字符串**（100 USDC = `"100000000"`，不是 `"100"`）
3. `owner_address`、`recipient` 都给值（问价时任意一个合法地址即可）
4. `expiration` 是**未来**的 Unix **秒**，不是毫秒
5. `gas_mode` 填 `"receive_less"` 或 `"pay_more"`

前两条占了我自己写错的绝大多数。符号和地址、小数和最小单位，
都是看起来对、发出去也不会拦你的写法。

## `expiration` 填什么最稳

Unix 秒，未来时间。稳妥的做法是拿链上时间加十分钟：

```bash
curl -s https://api.sera.cx/api/v1/system/time
```

用本地时间一般也行，机器时间准就没问题。

## 报价是按方向和金额分别给的

每个方向、每个金额都是单独的一次报价。想知道某个方向某个金额现在什么价，
就直接问那一档，不要拿另一档的结果去推。

要一次看很多档或很多币种，用批量接口：

```
POST /swap/quote/batch
```

请求体是 `{ "quotes": [ ...同样的对象数组... ] }`，比自己循环快很多。

## 固定成本是按笔收的

`gas_cost_usd` 实测在各个金额上都是 `"1.00"` —— **按笔收，不按百分比**。

这跟按比例抽成的路子是两种成本结构：金额越大，这一笔固定费用摊得越薄。
做成本模型的时候把它当固定项，不要当百分比，算出来的曲线才是对的。

## 我的服务器请求不通

`api.sera.cx` 在部分云厂商的出口白名单之外。表现是：

```
curl: (56) CONNECT tunnel failed, response 403
```

这是**你这边的网络策略**挡的。先用 `GET /health` 从别的网络确认一下。

## 数字和官网对不上

链上行情天天变。这个仓库里所有数据都标了实测日期，
**过期了就自己重跑**，命令都在文档里。

看到任何没有标日期的链上数字，都该怀疑一下。
